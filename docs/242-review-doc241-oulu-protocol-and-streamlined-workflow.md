A scope authorization must state the actual question, selected population, allowed evidence/actions, resource limits, objective completion test and genuine stop conditions. Within that authority, implement, run appropriate tests, prepare evidence, inspect it where authorized, verify/read back and publish results as one package. Every checkpoint must add evidence, resolve a specific defect or deliver a genuine scientific/owner decision.

Resource failure is a bounded failure report, not permission to swap candidates or silently reduce evidence.

Routine implementation choices, corrected wrapper/test invocation errors before evidence changes, deterministic serialization, receipt inventory, strict parsing and ledger derivation do not each need their own review. Fix reversible implementation defects within the authorized package, keep actual attempts/results honest, and review the final change once. Changes to scientific criteria, private owner answers or source identity are not routine fixes.
